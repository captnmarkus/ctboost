# Local CPython 3.12 integration

The checkout's CPython 3.12 native module was rebuilt from the final source and
activated at `ctboost/_core.cp312-win_amd64.pyd`. It now reports CTBoost 0.1.61,
MSVC 1950, C++17, CPU-only. Its SHA-256 is
`c5ea7e026942c3f1190ca5511fbf74f353bfeb08e7771f76bc5f6c1ca3e4d197`.

The previous 0.1.60 module was preserved at
`.tmp/improvements-20261016/original-native-cp312/_core.cp312-win_amd64.pyd`, with
SHA-256 `8f4e547a32ab131ed2b9d332dd7f17b4988716890d8f37ad95df881030c458db`.

The build used a fresh `.tmp/improvements-20261016/build-cp312` directory,
the existing `.venv` CPython 3.12.11 headers and library, and the existing
pybind11 2.x CMake package. Explicit MSVC 14.50.35717 and Windows SDK
10.0.26100.0 paths were inherited from the verified build command. Release
flags are `/O2 /Ob2 /DNDEBUG`; CUDA is disabled and native tests are enabled.
Compilation started after the inference ABBA measurements completed. No
dependencies were installed and no global environment was changed.

Validation passed:

- **90 bit-exact cached-versus-uncached prediction checks**, covering regression,
  binary classification and vector multiclass, row counts 0/1/64, prefixes
  0/1/7/all/99, missing values, nonzero input baselines and repeated predictions.
- Native state restoration, original leaf-index shapes, restored leaf-index
  equality, and unchanged model state.
- **Native CTest: 1/1 passed.** The first invocation hit a Python console-launcher
  mismatch before any test ran. Using CMake's native `ctest.exe` with process-local
  Python 3.12 paths resolved it; both logs are retained.

The smoke test loads `_core` directly with NumPy 2.5.2. It does not claim that
every Python wrapper or optional dependency in this environment was tested.
