# Inactive native-format feasibility: free-intercept absolute-leaf ridge

16 October 2026. Source inspection only. No model or dataset payload was opened, and no implementation, fitting, scoring, testing, build, or timing was performed. This note supplements [the mathematical hypothesis](absolute_leaf_ridge_hypothesis.md); it does not activate a successor to the current CV experiment.

The scalar squared-error case is feasible within existing native models. The new fold operation must explicitly allow the effective intercept to change and must enumerate every native leaf. The existing observed-leaf offset helper cannot be reused unchanged.

## Gauge, all leaves, and identity

For the centered solution `(b,w)`, freeze one common prediction-level rule:

`Fq = (1-q) F0 + q (b + Z w)`.

For CT/XGBoost, use `bq=(1-q)b0+q*b` and `thetaq=(1-q)theta0+q*w`. For LightGBM, the valid `b0=0` convention includes its old initial constant in `theta0`; the new constant is `q*b`, placed in all leaves of tree0. The centered optimum does not need the old constant to be recovered. This yields the same prediction-level blend in exact arithmetic, even though native rounding differs.

Enumerate the complete native tree/leaf map before designing observed columns. A fitting-unobserved column may be omitted from the sparse solve only with explicit optimum `w=0`: its blended contribution is `(1-q)*theta0`, not its unchanged old contribution. If it belongs to LightGBM's designated bias tree, it additionally receives the constant. Record that separately so the native storage convention is not mistaken for a penalized coefficient. Root-only trees remain valid constant partitions. Do not deduplicate physical leaf columns silently.

At `q=0`, return the original payload/model bytes through an explicit bypass. Rewriting then dividing by a learning rate can otherwise lose identity. At nonzero q, native outputs need a roundoff-aware oracle against both the full leaf sum and the prediction-level blend. A zero-tree LightGBM model has no existing leaf in which to store a free intercept and should initially be rejected; no synthetic bias tree is permitted. Tiny/zero float32 CT rates, nonfinite narrowed biases or weights, and overflow must fail before constructing an artifact.

## DART and unsupported predictions

Reject DART initially in all libraries. CT's DART currently rescales stored leaves, including earlier trees, before recording the ordinary learning rate; its effective predictor still uses their product. Its explicit `boosting_type` is available. [Dropped-tree adjustment](C:/apps/ctboost/src/core/booster_fit_iteration.cpp:69), [new-tree scaling and rate recording](C:/apps/ctboost/src/core/booster_fit_single_output.cpp:59).

**XGBoost3.4.1 has a version-specific guard hazard:** its `GBTree::SaveModel()` writes `name="gbtree"` even when dropout weights are present. Inspect the native `model.weight_drop` array, legacy wrapper weight fields, and active `dart_train_param` controls; name alone does not exclude DART. The future helper should reject any weighted/dropout layout rather than silently treat it as unweighted. This is a prospective support boundary, not evidence of DART in the frozen ordinary-boosting jobs. [Save/load and dropout controls](https://github.com/dmlc/xgboost/blob/v3.4.1/src/gbm/gbtree.cc#L443), [model weight persistence](https://github.com/dmlc/xgboost/blob/v3.4.1/src/gbm/gbtree_model.cc), [weighted scalar prediction](https://github.com/dmlc/xgboost/blob/v3.4.1/src/predictor/cpu_predictor.cc#L100).

LightGBM DART materializes rescaling in stored tree outputs. Nevertheless reject it and RF/`average_output` initially: ordinary prediction can divide by iteration count while raw-score prediction does not. Also reject linear-leaf trees, nonidentity-link regression objectives, multiclass/multi-target/vector leaves, unsupported deleted-node layouts, external row baselines/base margins/init scores, partial iteration ranges, prediction early termination, and constrained layouts outside the declared study. Freeze objective and booster controls from native state/configuration; a reloaded model's Python `params` alone may be incomplete. [DART rescaling](https://github.com/microsoft/LightGBM/blob/v4.7.0/src/boosting/dart.hpp#L157), [average-output conversion](https://github.com/microsoft/LightGBM/blob/v4.7.0/src/boosting/gbdt_prediction.cpp#L53).
